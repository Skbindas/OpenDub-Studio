# Repository discovery and search plan

OpenDub Studio is an experimental local-first AI video dubbing application, with a Hindi short-video validation path and optional personal Kaggle execution. Use this same bounded description across the README, repository About, release notes and future public website.

## GitHub metadata

- Description: `Experimental local-first AI video dubbing studio with speaker review, Hindi dubbing, resumable jobs and optional Kaggle processing. MIT application code; model terms vary.`
- Relevant topics: `ai-dubbing`, `video-dubbing`, `hindi`, `speech-to-text`, `text-to-speech`, `voice-cloning`, `speaker-diarization`, `video-localization`, `local-first`, `kaggle`, `python`, `fastapi`, `ffmpeg`, `open-source`.
- Version tag proposal: `v0.1.0-alpha.1`, attached only to a verified release commit after the release gates close.
- Topics describe the project; version tags identify source revisions. Issue labels organize work. These are different mechanisms.
- Do not add unrelated popular topics, fake stars, fabricated benchmarks, unsupported language counts or “best/number one” claims.
- Keep the README's introduction, installation link, limitation matrix, demo and FAQ readable without running JavaScript.

Topics improve classification, but neither topics nor a release tag guarantee Trending placement, search position or AI citations. Private repository results remain restricted to authorized viewers. Topic names themselves are public, so use ordinary descriptive terms only.

## Answer-friendly documentation

Use FAQ.md for concise answers about setup, licensing, uploads, speaker review, GPU availability and limitations. Link each answer to implementation/setup evidence. Keep one canonical product name, clear headings, descriptive image alt text and visible original-versus-dubbed labels. Update dated claims when tested behavior changes.

## Public website work, after a URL is chosen

1. Publish a lightweight accessible product page with a unique title and description, setup link, honest limitations and the approved before/after pair. Keep private runtime endpoints off the public host.
2. Set canonical and Open Graph URLs to the actual public URL, with an original approved brand image. Add appropriate SoftwareSourceCode/SoftwareApplication structured data only for facts also visible on the page. Do not invent reviews, ratings or pricing.
3. Verify HTTP status, mobile rendering, internal links, robots access, sitemap and indexed canonical URL. Use Search Console for indexing and query evidence; use GitHub traffic for repository visits. Record an initial baseline before judging improvements.
4. Write useful task pages such as “Dub a short video into Hindi locally” and “Review speaker voices before export.” Demonstrate tested results, not keyword repetition.
5. Link the public site and repository in both directions. Keep source release, model terms and demo permissions visible.

Google states that normal SEO fundamentals apply to AI Overviews/AI Mode; there is no special AI schema or machine-readable file required for inclusion. A future `llms.txt` may be a navigation convenience, but it is not an indexing or ranking guarantee. Search Console setup and deployment require the final approved domain/account.
